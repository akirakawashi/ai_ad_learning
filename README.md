# AI Ad Learning

Подготовка данных для дообучения детектора щитов. Фотографии прогоняются через
рабочую модель, разметка сохраняется в YOLO-формате, а отчёт показывает, какие
кадры править руками в первую очередь.

Соседние репозитории: `../ai_ad_ml` — пайплайн и воркер, откуда взяты веса,
`../ai_ad_backend` — канон и документация проекта.

## Требования

- Python 3.12 и `uv`;
- GPU (без неё прогон идёт на процессоре и занимает часы);
- веса детектора в `models/detection/best.pt` — копия из `../ai_ad_ml`;
- фотографии в `raw/`.

Ни веса, ни фотографии, ни результат прогона в Git не попадают.

## Настройка

```bash
uv sync
cp ../ai_ad_ml/models/detection/best.pt models/detection/best.pt
```

Версия `ultralytics` закреплена ровно той, что стоит в пайплайне. Разметка должна
получиться такой же, какую увидит рабочая модель, иначе правится не то.

## Запуск

```bash
uv run python run_prelabel.py
```

Полезные ключи: `--source` и `--output` для других папок, `--conf` для порога
записи рамки, `--weak-conf` для границы «посмотреть глазами», `--imgsz`,
`--batch`, `--device`.

## Что на выходе

```text
prelabel/
├── labels/              разметка, по .txt на каждую фотографию
├── images/              симлинки на raw — датасет для обучения
├── data.yaml            описание набора для ultralytics
├── report.csv           строка на фотографию: рамки, уверенность, статус
├── review.txt           порядок ручной проверки
└── cvat_annotations.zip импорт разметки в CVAT
```

Пустой `.txt` означает «на кадре ничего нет» и остаётся на месте намеренно:
отрицательные примеры нужны обучению не меньше положительных.

## Правка в CVAT

```bash
uv run python run_review_bundle.py
```

Собирает пачки только из кадров, которым нужен человек: `part_NN_images.zip` и
парный к нему `part_NN_annotations.zip`. Уверенные кадры в пачки не идут.

Порядок в CVAT такой. Заводится метка **`ad_object`** — имя должно совпасть
буквально, иначе импорт ничего не найдёт и молча создаст пустую задачу. Задача
создаётся из `part_NN_images.zip`, затем `Actions → Upload annotations →
YOLO 1.1 → part_NN_annotations.zip`. После правки — `Actions → Export
annotations → YOLO 1.1`, и выгруженная разметка кладётся поверх `prelabel/labels`.

Если нужен весь набор целиком, а не только спорные кадры, задача создаётся из
папки `raw/`, а разметка заливается из `cvat_annotations.zip` — там лежат все
7742 файла.

Порог записи рамки ниже боевого: стереть лишнюю рамку быстрее, чем нарисовать
пропущенную. Обратная сторона — часть рамок окажется мусором, и их надо снять.

Смотреть все 7742 кадра подряд незачем. `review.txt` ставит вперёд кадры, где
модель не нашла ничего, за ними — кадры со слабыми рамками, от самой сомнительной.
Уверенные кадры в список не попадают.

Уверенность в YOLO-формате не хранится, и в CVAT рамка на 0.26 выглядит так же,
как рамка на 0.95. Различить их можно только по `report.csv`.

## Набор для обучения

```bash
uv run python run_build_dataset.py --export "выгрузка_из_cvat.zip"
```

Распаковывает ручную разметку из CVAT, добавляет кадры, которые модель разметила
уверенно, и делит всё вместе на три части:

- **обучение** — на нём модель учится;
- **проверка** — по ней выбирается лучшая эпоха и срабатывает ранняя остановка;
- **тест** — в обучении не участвует вовсе, по нему сравниваются модели.

Пропорция 70 / 15 / 15. Внутри теста отдельно лежит `test_handmade` — те его
кадры, что размечены человеком. На остальных разметку поставила текущая модель, и
метрика там показывает согласие с ней: сама с собой она сходится почти идеально.

Не участвуют только кадры, где модель сомневалась: их разметка заведомо кривая и
до правки в CVAT она набор портит.

Деление идёт внутри пар «группа съёмки и наличие рамок». Группа — кадры с
регистратора, студийные снимки, выгрузка из интернета — разводится по всем частям,
иначе рабочий домен окажется только в обучении. Кадры без рамок делятся отдельно:
их заметная доля, и это не мусор, а обучение не выдумывать щит там, где его нет.
Собравшись в одной части, они перекосили бы и обучение, и метрику.

Что стоит помнить при чтении цифр: часть разметки в проверке и тесте поставила
текущая модель. На этих кадрах метрика измеряет согласие с ней, а не правоту. Чем
больше кадров пройдёт через ручную правку, тем честнее становится оценка.

## Обучение

```bash
uv run python run_eval.py --weights models/detection/best.pt        # точка отсчёта
uv run python run_train.py                                          # обучение
uv run python run_eval.py --weights models/detection/best.pt runs/ad_object_v2/weights/best.pt
```

По умолчанию берётся предобученная `yolo11m`, 120 эпох, `imgsz 960`, батч 10,
ранняя остановка после 20 эпох без улучшения. Разрешение повторяет боевое: модель,
обученная в другом, поведёт себя в пайплайне иначе.

Дообучить текущую рабочую модель вместо обучения заново — `--weights
models/detection/best.pt`. Но большая часть нового набора размечена ею же, и
подтверждать собственные ответы она будет охотнее, чем учиться новому.

`run_eval.py` считает по `test_handmade` — единственной части, где разметка
человеческая. `--split test` добавит к ней кадры с машинной разметкой, `--split
val` покажет ту часть, на которую опиралось обучение. Разброс между ними и есть
мера того, насколько цифре можно верить.

Перед обучением набор стоит проверить:

```bash
uv run python run_check_dataset.py
```

Ищет кадры без разметки и разметку без кадров, битые ссылки, нечитаемые
фотографии, испорченные строки, координаты за границей кадра, вырожденные рамки и
пересечения между частями. Последнее не теория: при пересборке с другим делением
ссылки от прошлого раза однажды остались лежать, и 2388 кадров оказались сразу в
двух частях.
