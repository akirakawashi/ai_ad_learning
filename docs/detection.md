# Детектор щитов

Что происходит на каждом шаге и почему именно так. Команды и структура папок —
в [README](../README.md).

## Псевдоразметка

```bash
uv run adlearn detect prelabel
```

Фотографии из `data/raw/` прогоняются через рабочую модель, разметка ложится в
`data/detection/prelabel/`:

```text
labels/               разметка, по .txt на каждую фотографию
images/               ссылки на data/raw — набор для обучения
data.yaml             описание набора для ultralytics
report.csv            строка на фотографию: рамки, уверенность, статус
review.txt            порядок ручной проверки
cvat_annotations.zip  импорт разметки в CVAT
```

Порог записи рамки (`--conf`, по умолчанию 0.25) ниже боевого 0.50 намеренно:
стереть лишнюю рамку в разметчике — одно движение, нарисовать пропущенную —
десять. Обратная сторона — часть рамок окажется мусором, и их надо снять.

`--imgsz` и порог IoU повторяют боевые значения из `DetectionConfig` пайплайна:
разметка должна получиться такой же, какую увидит рабочая модель.

Пустой `.txt` означает «на кадре ничего нет» и остаётся на месте намеренно.
Отсутствующий файл значит «кадр не размечен», и обучение молча его пропустит
вместо того, чтобы учиться на отрицательном примере.

## Статусы и порядок проверки

Каждый кадр получает статус:

| статус | что значит |
| --- | --- |
| `пусто` | модель не нашла ничего — промах целиком или нетипичный щит |
| `слабая` | самая слабая рамка ниже `--weak-conf` (0.50) |
| `ок` | все рамки уверенные |

`review.txt` ставит вперёд пустые кадры, за ними слабые — от самой сомнительной.
Уверенные в список не попадают: смотреть все семь с половиной тысяч кадров
подряд незачем.

Уверенность в YOLO-формате не хранится, и после импорта в CVAT рамка на 0.26
выглядит ровно так же, как рамка на 0.95. Различить их можно только по
`report.csv` — ради этого он и пишется.

## Проверка псевдоразметки

```bash
uv run adlearn detect review --stage scan
uv run adlearn detect review --stage judge
uv run adlearn detect review --stage sheets
```

Набор для второй модели собрали из разметки первой, и никто её не смотрел.
Модель подтверждала собственные ответы: закрепляла промахи, а кадров без щитов
в наборе не оказалось вовсе. Проверка от 04.09.2026 это исправила.

Детектор размечает папку заново и рядом с каждой рамкой сохраняет вырезку и
уверенность: YOLO-формат уверенность не хранит, а без неё нечем упорядочить
проверку. Потом VLM отвечает по каждой вырезке, что на ней: рекламная плоскость,
вывеска, реклама на транспорте, дорожный знак, стена, машина. Человек смотрит
только спорное — листы в `review/sheets/` — и пишет вердикты в
`review/verdicts.csv`: `оставить`, `убрать` или `спорно`.

Судья ошибается в одну сторону: рекламный указатель с телефоном или расстоянием
он зовёт дорожным знаком. На 10 445 рамках он отклонил 832, из них человек
вернул 105 и ещё 93 отдал в CVAT. Принятые рамки чистые: на 96 уверенных
ошибок не нашлось, на 523 слабых — шесть.

Что считается рекламной поверхностью, решил владелец: щиты, вывески и реклама
на бортах транспорта — да, табло цен на заправках и дорожные указатели — нет.

`--stage apply` складывает чистую разметку в `review/labels/`, не трогая
исходную. Кадр со спорной рамкой туда не попадает, а уходит пачкой в CVAT
(`--stage cvat`), выгрузка возвращается через `--stage import`. Кадры, где
детектор не нашёл ничего, на стоковых фото в набор не идут: реклама там почти
всегда есть, просто модель её не увидела, а рисовать щиты на 733 стоковых
макетах владелец 04.09.2026 решил не тратить время. На записи с регистратора
наоборот — такие кадры честно пусты, и `--empty-stride N` делает каждый N-й
негативом.

## Отрицательные примеры со стороны

```bash
uv run adlearn detect negatives --source ../негатив --skip "delko.jpg"
```

Детектор принимает борт фуры за щит. Владелец собрал 123 фотографии фур без
рекламы, семь с крупными логотипами перевозчиков отложены: по правилу реклама
на борту это реклама, и пустой файл к ним был бы ложью. Остальные легли в
`data/detection/negatives/` с пустой разметкой и по одной копии на кадр:
отражение, случайный кроп, сдвиг яркости и контраста, лёгкое размытие. Копия
помечена суффиксом `_aug` и при сборке остаётся в обучении рядом с оригиналом,
иначе модель увидит на проверке то, что уже видела.

## Набор для обучения

```bash
uv run adlearn detect build3
```

Собирает набор из четырёх источников: ручная разметка владельца, проверенный
сток, кадры с регистратора и фотографии без рекламы. Кадры кладутся ссылками,
диск не удваивается.

| источник | кадров | из них без рамок |
| --- | --- | --- |
| ручная разметка владельца | 1783 | 483 |
| сток после проверки | 7009 | 58 |
| регистратор NO20260509 | 783 | 231 |
| фуры и автобусы | 223 | 223 |

Негативов выходит десятая часть набора против нуля в прежнем: кадров без рамок
там не было вовсе, и модель принимала за щит борт фуры, дорожный знак и стену.
Пустые кадры записи прореживаются, `--negative-stride` задаёт, какой по счёту
брать: их на записи больше, чем всего остального вместе, и взять все значит
научить модель молчать там, где щит есть.

Повторы отбрасываются по имени, размеру и началу файла. Один и тот же кадр
лежит в старых выгрузках дважды с разной разметкой, а среди фотографий из
интернета попадаются одинаковые снимки под разными именами; разъехавшись по
частям, такой кадр превращает тест в проверку на уже виденном. По той же
причине отражённая копия фуры едет в ту же часть, что и оригинал.

### Отложенная съёмка

`test_dashcam` — 158 кадров записи `VideoProject`, снятой отдельно. В делении
они не участвуют и в обучение не попадают ни одним кадром. Обычный `test`
честен по разметке, но состоит из тех же записей, что и обучение: соседние
кадры, те же щиты, тот же свет, и метрика на нём выше настоящей. Сравнивать
модели между собой нужно по отложенной части, а разброс между двумя цифрами
показывает, насколько метрике можно верить.

### Старая сборка

```bash
uv run adlearn detect build --export выгрузка_из_cvat.zip
```

Распаковывает ручную разметку из CVAT, добавляет кадры со статусом `ок` и делит
всё вместе на три части, 70 / 15 / 15:

- **обучение** — на нём модель учится;
- **проверка** (`val`) — по ней выбирается лучшая эпоха и срабатывает ранняя остановка;
- **тест** — в обучении не участвует вовсе, по нему сравниваются модели.

Кадры со статусами `пусто` и `слабая` в набор не идут: их разметка заведомо
кривая и до правки в CVAT она набор портит.

Внутри теста отдельно лежит `test_handmade` — те его кадры, что размечены
человеком. На остальных разметку поставила текущая модель, и метрика там
показывает согласие с ней, а не правоту: сама с собой она сходится почти
идеально.

### Как делится

Деление идёт внутри пар «группа съёмки и наличие рамок».

Группа читается из имени файла: `video_hard_000187.jpg` → `video_hard`,
`3f9c1a2b8e04.jpg` → `raw`. Это кадры с регистратора, студийные снимки, выгрузка
из интернета — каждый род должен попасть во все три части, иначе рабочий домен
окажется только в обучении.

Кадры без рамок делятся отдельно: их заметная доля, и это не мусор, а обучение не
выдумывать щит там, где его нет. Собравшись в одной части, они перекосили бы и
обучение, и метрику.

Страта меньше трёх кадров уходит в обучение целиком: тест из одного кадра ничего
не измеряет, а обучение теряет и этот кадр.

Деление воспроизводится: при том же `--seed` получается тот же результат.

## Проверка набора

```bash
uv run adlearn detect check
```

Ищет кадры без разметки и разметку без кадров, битые ссылки, нечитаемые
фотографии, испорченные строки, координаты за границей кадра, вырожденные рамки и
пересечения между частями.

Последнее не теория: при пересборке с другим делением ссылки от прошлого раза
однажды остались лежать, и 2388 кадров оказались сразу в двух частях. Поэтому
`build` теперь чистит папку части перед тем, как её заполнить, а проверка сверяет
и имена, и содержимое файлов.

`--skip-decode` пропускает открытие каждого кадра — быстрее, но нечитаемые не
найдутся.

## Просмотр глазами

```bash
uv run adlearn detect preview --split train
uv run adlearn detect preview --split train --only-empty
```

Собирает контактные листы: кадр с рамками, по дюжине на лист. Смотреть семь тысяч
кадров по одному невозможно, а лист просматривается за секунды — и промах видно
сразу. `--only-empty` оставляет кадры без рамок, там промах виден вернее всего.

## Обучение

```bash
uv run adlearn detect eval --weights models/detection/best.pt   # точка отсчёта
uv run adlearn detect train
uv run adlearn detect eval --weights models/detection/best.pt \
    data/runs/ad_object_v2/weights/best.pt
```

По умолчанию берётся предобученная `yolo11m`, 120 эпох, `imgsz 960`, батч 10,
ранняя остановка после 20 эпох без улучшения. Разрешение повторяет боевое:
модель, обученная в другом, поведёт себя в пайплайне иначе.

Старт с предобученных весов, а не с текущей рабочей модели — тоже намеренно.
Дообучать модель на разметке, которую она же и поставила, почти бессмысленно: она
подтвердит собственные ответы и закрепит собственные промахи. Продолжить с боевых
весов можно явно: `--weights models/detection/best.pt`.

`eval` считает по `test_handmade` — единственной части, где разметка
человеческая. `--split test` добавит к ней кадры с машинной разметкой, `--split
val` покажет ту часть, на которую опиралось обучение. Разброс между ними и есть
мера того, насколько цифре можно верить.

Чем больше кадров пройдёт через ручную правку, тем честнее становится оценка.
